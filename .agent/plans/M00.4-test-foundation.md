# M00.4 — Test Foundation

## Current State

- Milestone: [M00 — Foundation](../../docs/milestones/M00-foundation.md), Slice M00.4.
- The app is a Frappe 16.36.1 scaffold. `development.localhost` is the only
  existing site and is a development site with `frappe`, `itnovel_common`, and

- Frappe 16 provides `bench --site <site> run-tests --app <app>`. Its runner

- `frontend/package.json` has Vite 7, Vue 3, `dev`, `build`, and `type-check`
  scripts, but no Vitest, Jest, Cypress, Playwright, or other frontend test
  runner. The installed dependency tree confirms the same absence.
- Existing uncommitted `README.md` and `frontend/src/pages/Home.vue` changes
  belong to M00.3 and must be preserved. Existing M00.1–M00.3 plans are

## Goal

Provide a small, repeatable test foundation: a dedicated Frappe test site with
a confirmed backend smoke command, and one frontend smoke test run by a minimal
Vue/Vite-native runner.

## Non-Goals

- No Service, Request, Workflow, Task, Approval, Knowledge Base, or other
  business DocType, product API, provider layer, fixture library, CI, coverage
  gate, e2e framework, Docker redesign, or `itnovel_common` change.
- No tests against `development.localhost`, no use of its data as fixtures, and
  no destructive reset, restore, or database operation on that site.
- No M00.5 work.

## Backend Test Strategy

Add `service_hub_system/tests/test_smoke.py` with a `FrappeTestCase` that only
imports `service_hub_system` and asserts the scaffold package exposes its
version. It creates no document and reads no corporate or development data.
Use Frappe's supported runner:

```bash
cd /workspace/development/frappe-bench
bench --site service-hub-tests.localhost run-tests --app service_hub_system
```

The command must run only after the site is created, the app is installed, and
`allow_tests` is enabled on that named site. It must report one passing test.

## Test Isolation

Create the dedicated `service-hub-tests.localhost` site in the existing Bench,
with its own newly created MariaDB database and only `frappe` plus
`service_hub_system` installed. Obtain the MariaDB root credential from the
local protected development configuration; do not commit or document it.

Bootstrap only after confirming the target name is absent, never pass `--force`,
and never point a new-site/install/config/test command at
`development.localhost`:

```bash
cd /workspace/development/frappe-bench
bench new-site service-hub-tests.localhost --install-app service_hub_system
bench --site service-hub-tests.localhost set-config allow_tests true
bench --site service-hub-tests.localhost list-apps
```

The bootstrap intentionally changes only the new test site and database. Test
records remain confined there. Future destructive recreation or removal of this
test site is outside this Slice and requires an explicit request after checking
the exact site name.

## Frontend Test Strategy

Install the small, Vite-native development-only set `vitest` and `jsdom` in
`frontend/`; update the npm lockfile through npm. Add a `test` script (`vitest
run`), a separate `vitest.config.ts` using the existing Vue plugin and jsdom,
and a smoke spec for the existing Vue router. The test verifies that the
fallback route resolves; it makes no HTTP request and uses no product data.

This is deliberately smaller than Playwright/Cypress and does not alter the
existing Vite startup/build configuration. If the installed Vue/Vite versions
cannot run this standard stack without a significant dependency/tooling change,
stop and report the incompatibility rather than replacing the frontend setup.

## Risks

- Frappe's runner may write test records to its selected site; the named test
  site is the mandatory containment boundary.
- The new site needs existing local MariaDB bootstrap credentials. Passing a
  wrong target or using `--force` is a STOP condition.
- Npm package installation needs registry access. A dependency conflict or a
  change beyond this small development-only set is a STOP condition.
- Existing M00.3 worktree changes must not be reformatted, reverted, or used as
  a test fixture.

## Rollback

Source, lockfile, documentation, and plan changes are ordinary Git-revertible
changes. The dedicated site's database is isolated; do not delete it
automatically. If its later removal is requested, first verify the exact named
site and confirm that it contains no material data.
