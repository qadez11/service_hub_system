# M00 — Foundation

План разработки. Он не подтверждает готовность текущего приложения.
Бюджеты — оценки объема контекста и проверки, а не сроки.

## Goal

Подготовить воспроизводимую среду Frappe/Frappe UI, проверки и границу корпоративных данных.

## User Result

Разработчик запускает приложение и выполняет базовые проверки по документации.
Команда знает, какие данные принадлежат существующему app.

## Why Now

Без воспроизводимой среды нельзя отличить дефект Slice от проблемы окружения.
Контракты identity и providers нужны до создания Request.

## Dependencies

[PRODUCT](../../PRODUCT.md), [ARCHITECTURE](../../ARCHITECTURE.md) и [ADR-004](../adr/ADR-004-existing-app-boundary.md).
Доступ к утвержденному dev site и корпоративной документации требуется до интеграционной проверки.

## Scope

- Проверить app, Bench, dev site, Frappe UI и frontend entry point.
- Зафиксировать версии, команды запуска, test/lint/build и ограничения среды.
- Определить владельцев пользователей, Team, оргструктуры, документов и фактов работы.
- Описать provider boundary и минимальный контракт будущего адаптера.
- Подготовить базовые тесты, lint и CI.
- Проверить доступность frappe-skills и маршрут чтения документации.
- Зафиксировать техническую модель M01 без реализации бизнес-workflow.

Наблюдение на 2026-10-05: app и frontend scaffold уже есть.
Локальная копия Frappe сообщает 16.36.1; pyproject требует Python >=3.14.
Frontend использует Vue 3/Frappe UI/Vite/TypeScript и требует Node >=20.19.0.
В package.json есть dev/build и frontend type-check; pre-commit содержит ruff, eslint и prettier.
В common_site_config задан developer_mode=1. Это не проверка работоспособности конкретного site.
Собственный CI и бизнес-тесты в просмотренном дереве не обнаружены.
Существующие незакоммиченные изменения нужно изучить перед продолжением.

## Out of Scope

Service Designer, business workflow, бизнес-DocType Request/Task, migrations корпоративных данных и реальные integration actions.
M00 может описать модель следующего milestone, но не реализует ее.

## Slices

| Slice | Малый результат | Проверка завершения | Budget |
|---|---|---|---|
| M00.1 Инвентаризация | Точные app/site/version/tooling и описание существующих изменений | Команды и ограничения подтверждены выводом; секреты не попали в документы | S |
| M00.2 Запуск backend | Повторяемая инструкция dev site | Новый сеанс достигает приложения; ошибка запуска воспроизводима | S |
| M00.3 Запуск frontend | Frappe UI связан с нужным backend | Страница открывается; build/type-check проходят | S |
| M00.4 Проверки | Рабочие команды тестов и lint | Один smoke test проходит; намеренно сломанная проверка обнаруживает ошибку | S |
| M00.5 CI | Базовый pipeline для выбранных проверок | Pipeline запускается и сообщает failure при нарушении | S |
| M00.6 Граница данных | Mapping корпоративных источников и минимальный provider contract | Пример разрешенного и запрещенного чтения описан и проверяем | M |
| M00.7 Контракт M01 | Решения по минимальной модели, графу, статусам и безопасности | Нет скрытых решений, блокирующих M01.1 | M |
| M00.8 Документация и skills | Путь входа для следующего агента | Другой разработчик находит команды и создает конкретный ExecPlan | S |

Slice M00.6 не создает новый справочник людей.
Slice M00.7 заканчивается документированным решением, а не workflow implementation.
Если один Slice требует нескольких независимых решений, его нужно дополнительно разделить.

## Acceptance Criteria

1. Известно, какой site используется и какие app установлены на нем.
2. Backend и frontend запускаются по записанным командам.
3. Tests, lint, type-check и build имеют воспроизводимый результат.
4. CI запускает согласованный набор проверок.
5. Provider mapping не подменяет неизвестные источники предположениями.
6. Следующий агент понимает разницу между целевой архитектурой и существующим scaffold.

## Required Tests

- Smoke test запуска приложения и доступности frontend.
- Проверка связи frontend с правильным site.
- Test/lint/type-check/build в выбранном dev environment.
- CI: успешный путь и обнаружение намеренного дефекта проверки.
- Проверка отсутствия секретов в инструкциях и output CI.

Точные команды устанавливает M00.1. Этот документ не заявляет, что они уже проверены.

## AI Budget

L. Выполнять отдельными Slice; M00.7 делить при накоплении архитектурных решений.

## Exit Criteria

Запуск и проверки воспроизводимы. CI работает.
Граница корпоративных данных записана. Блокирующие решения M01 утверждены.
У M01.1 есть конкретный ExecPlan.

## Known Risks

Локальный scaffold может не совпадать с рабочим site.
Версии в manifest не гарантируют установленный runtime.
Соседний itnovel_common имеет собственные архитектурные контракты.

## Decision Required

[D-21](../architecture/existing-app-boundary.md): точные provider contracts.
[Q01–Q05, Q11](../product/overview.md): identity, чувствительность, компании, нагрузка, SSO и миграция команд.
[D-07](../architecture/domain-model.md), [D-22](../adr/ADR-003-workflow-definition-format.md): минимальная модель и формат графа.
Нужно выбрать CI и test environment по фактической инфраструктуре. Исходник их не задает.
