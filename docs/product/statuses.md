# Состояния и публичное представление

Основание: исходный PRODUCT draft 0.1, разделы 7, 9–12, 18, 26, 30.


## Области состояний

Public Status MUST NOT совпадать по смыслу с полным состоянием workflow.
Task, Node Run, Service и Knowledge Article имеют отдельные наборы состояний.
В этом документе находится основной справочник значений.

| Объект | Значения из исходника | Степень определенности |
|---|---|---|
| Service | `Draft`, `Active`, `Deprecated`, `Archived` | Перечень задан; полная таблица переходов не задана |
| Public Status | «Черновик», «Принята», «Выполняется», «Ожидаем вас», «На согласовании», «Завершена», «Отказано», «Отменена», «Нужна помощь» | Рекомендуемый фиксированный набор; Service не обязана использовать все значения |
| Task | `Open`, `Claimed`, `In Progress`, `Waiting`, `Completed`, `Cancelled`, `Escalated` | Перечень задан; полная таблица переходов не задана |
| Node Run | `queued`, `running`, `waiting`, `completed`, `failed`, `cancelled`, `skipped` | Перечень задан; переходы требуют спецификации Slice |
| Knowledge Article | `Draft`, `Published`, `Archived` | Перечень задан |
| Результат Approval | `approved`, `rejected`, `returned`, `cancelled` | Это результат согласования, а не статус Task |
| Internal Status Request | Не задан | Не выводить значения из статусов Task или Node Run |
| Workflow Execution | Не задан | Не придумывать enum до проектирования runtime |

`Ready to Publish`, `Release N active` и `Draft for N+1` в исходной схеме описывают этапы подготовки.
Исходник не объявляет их значениями поля `Service.status`.

## Mapping Public Status

Service Release хранит правило отображения внутреннего состояния в Public Status.
Исходник дает следующие примеры:

| Внутреннее событие или состояние | Public Status |
|---|---|
| Активна Human Task | «Выполняется» |
| Активна Approval | «На согласовании» |
| Request Information ожидает ответ | «Ожидаем вас» |
| Техническая ошибка требует ручного вмешательства | «Нужна помощь» либо безопасный статус по политике |

Это примеры mapping, а не полная таблица переходов.
Техническая ошибка MUST NOT раскрывать stack trace или секреты.

## Безопасная история

Requester видит создание Request, начало работы, запрос информации, свой ответ, согласование и завершение.
Система не публикует внутренние имена Node и технические сообщения.
Состав представления находится в [PublicRequestView](../architecture/permissions.md).

> DECISION REQUIRED — D-02: переходы и конкурирующие состояния.
> Не определены полные переходы, приоритеты mapping параллельных веток и enum Internal Status/Workflow Execution.
> Это влияет на допустимые действия и стабильность Public Status.
> Исходник дает примеры mapping и допускает «Нужна помощь» либо сохранение безопасного статуса.
> До реализации Slice нужно утвердить используемые переходы; до M05 — правило выбора статуса при нескольких активных ветках.
>
> DECISION REQUIRED — D-04: черновик Request и фиксация Service Release.
> Есть действие сохранения черновика. Его модель и момент создания Request пока не определены.
> Это влияет на форму после публикации нового Service Release.
> До поддержки черновиков нужно определить их модель и поведение устаревшей формы.
> При создании Request система MUST выбрать ровно один Service Release и сохранить ссылку на весь срок жизни Request.
> После создания `Request.service_release` MUST NOT изменяться, в том числе при submit.
> D-04 MUST сохранять [инвариант связи](../architecture/service-release.md) и не разрешает отложить фиксацию ссылки уже созданной Request.
