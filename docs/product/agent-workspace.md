Основание: исходный PRODUCT draft 0.1, разделы 11, 22, 28, 43.


## Очереди

Очередь — представление Task по фильтрам. Она не создает отдельную Request.
Примеры: задачи IT Support, неназначенные, мои, просроченные, SLA меньше двух часов, согласования, VIP.
Менеджер команды может сохранять общие представления очередей.

Слева интерфейс показывает сохраненные очереди, счетчики и быстрые фильтры.
В центре он показывает Task с сортировкой по SLA, приоритету и возрасту.
Справа или на отдельной странице он показывает детали Task.

## Детали Task и Request

Исполнитель видит разрешенные данные Request, текущую Task, публичную переписку и Internal Note.
Интерфейс показывает связанные документы и разрешенные действия.
Для внутренней страницы Request предусмотрены Internal Status, активные Task, Workflow Execution, SLA и выдержки аудита.
Технические действия доступны только с правом.

Claim возвращает актуальное состояние, если другой исполнитель уже забрал Task.
Техническая гарантия атомарности и критерий проверки находятся в [назначении Task](../architecture/task-assignment.md).

Связанные Knowledge Article можно подбирать по Service и Node.
Пример: Task «Настроить ноутбук» показывает инструкцию IT-инженеру.
