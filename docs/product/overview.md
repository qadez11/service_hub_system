# Продукт и границы

Основание: исходный PRODUCT draft 0.1, разделы 1–5, 27–29, 52–56.


## Назначение

«Единое окно» — внутренняя корпоративная платформа услуг.
Сотрудник выбирает результат без знания структуры подразделений.
Одна потребность сохраняет один пользовательский контекст: Service → Request → статус → коммуникация → результат.

Продукт решает проблемы разрозненных почты, чатов, таблиц, форм, ITSM, 1С и Wiki.
Он делает правила исполнения, ответственность, согласования и историю решения явными.
Изменения Service не должны нарушать исполнение ранее созданных Request.

Примеры потребностей: доступ, рабочее место, справка, закупка, договор, техническая проблема.
Другие примеры: изменение данных, консультация, внутренняя процедура, межфункциональный процесс.

## Аналитика

| Аудитория | Метрики |
|---|---|
| Владелец услуги | Число Request; median/p90 resolution time; SLA compliance; cancellation rate; rejection rate; reopen rate; CSAT; bottleneck nodes; среднее время этапов |
| Менеджер команды | Размер очереди; oldest task; breached/near-breach tasks; throughput; workload by assignee; unassigned aging |
| Платформа | Активные Service; workflow failures; integration errors; top requested services; search queries with no result |

> DECISION REQUIRED — D-01: reopen.
> Не определено действие повторного открытия Request, хотя аналитика требует reopen rate.
> Это влияет на lifecycle, Workflow Execution и расчет метрики.
> Текст допускает учет повторного открытия, но не задает его поведение.
> До реализации метрики нужно определить lifecycle либо исключить метрику из конкретного выпуска с явным решением.

CSAT описан в [Request](requests.md).
Целевые показатели производительности и масштаба находятся в [архитектурном обзоре](../architecture/overview.md).

## Пилот

Рекомендуемый пилот включает понятные Service с 2–4 внутренними участниками.
В наборе должны быть согласование и измеримый результат.
Предпочтительны процессы, которые сейчас выполняются через почту или чат.
Исходник рекомендует не начинать с payroll и юридически значимых операций.

Предлагаемый набор:

1. Доступ к внутренней системе.
2. Проблема с рабочим оборудованием.
3. Заказ нового оборудования.
4. Подготовка рабочего места нового сотрудника.

Это рекомендация для выбора пилота, а не утвержденный список корпоративных Service.
[Эталонные сценарии](requests.md) задают проверку пилота к завершению M10.
[M01](../milestones/M01-request-happy-path.md) проверяет только упрощенный сквозной путь.
